Getting Started

Install BedrockPlus, initialize a safe server directory and confirm the exact supported environment.

Requirements

  • Windows 10/11 x64
  • Python 3.13 x64
  • Visual Studio 2022 with the C++ desktop workload and CMake
  • Internet access for the first official BDS download
  • Acceptance of the applicable Minecraft server terms

Install BedrockPlus

Use the production PyPI package. Upgrade uses the same command with --upgrade.

py -3.13 -m pip install --upgrade bedrockplus

Initialize and start a server

Run BedrockPlus inside the directory that should own the server. Existing worlds, plugins and packs are preserved by the adoption and update workflow.

mkdir D:\Minecraft\MyServer
cd D:\Minecraft\MyServer
bedrockplus
Server-local command

Initialization places bedrockplus.exe beside bedrock_server.exe, so the server can be managed without depending on a global command later.

Subscribe to player.join

Subscribe when the server is ready, retain the subscription ID and remove it during stopping. The event provides a typed Player object.

from bedrockplus import PlayerJoinEvent, Plugin, Server

class JoinReporter(Plugin):
    def on_load(self) -> None:
        self.server = Server(self.host)
        self.join_subscription = None

    def on_server_ready(self) -> None:
        self.join_subscription = self.host.subscribe_event(
            "player.join", self.on_player_join
        )
        self.host.log("Join Reporter is ready")

    def on_player_join(self, event: PlayerJoinEvent) -> None:
        player = event.player
        self.host.log(player.name, "joined with XUID", player.xuid)

    def on_server_stopping(self) -> None:
        if self.join_subscription is not None:
            self.host.unsubscribe_event(self.join_subscription)
            self.join_subscription = None
#include <bedrockplus/sdk/plugin.hpp>

class JoinReporter final : public bedrockplus::sdk::Plugin {
public:
    using Plugin::Plugin;

    void on_server_ready() override {
        join_listener_ = events().subscribe<bedrockplus::sdk::PlayerJoinEvent>(
            [this](const auto& event) {
                logger().info(event.player().name + " joined");
            });
    }

    void on_disable() override {
        if (join_listener_ != 0) events().unsubscribe(join_listener_);
    }

private:
    std::uint64_t join_listener_{};
};

BEDROCKPLUS_PLUGIN(
    JoinReporter,
    "example.join-reporter",
    "Join Reporter",
    "1.0.0")
Plugin-owned messages

BedrockPlus does not print automatic successful load/enable notices. Log only the lifecycle information that is useful for your plugin.

Validate and package

cd plugins\JoinReporter
bedrockplus plugin pack
One-time C++ toolchain

Install Visual Studio 2022 Build Tools with Desktop development with C++. Select MSVC x64/x86 build tools, a Windows SDK and CMake tools for Windows. The Visual Studio graphical IDE is optional.

  1. CMakechecks the project and generates Visual Studio/MSBuild files.
  2. MSVCcompiles the C++ source into the DLL named by manifest.json.
  3. bedrockplus plugin packvalidates manifest.json plus the compiled DLL and creates the .bppack archive.
Current SDK requirement

BEDROCKPLUS_ROOT must be a directory containing include/bedrockplus/sdk/plugin.hpp. BedrockPlus 1.1.0 has not yet published a standalone C++ SDK archive, so rebuilding the source example currently requires the BedrockPlus developer checkout. The ready .bppack does not.

Run these commands in Developer PowerShell for VS 2022 after replacing the SDK path:

$env:BEDROCKPLUS_ROOT = "D:\Path\To\BedrockPlusSdk"
Test-Path "$env:BEDROCKPLUS_ROOT\include\bedrockplus\sdk\plugin.hpp"

cmake -S . -B build -G "Visual Studio 17 2022" -A x64 `
  -DBEDROCKPLUS_ROOT="$env:BEDROCKPLUS_ROOT"
cmake --build build --config Release
bedrockplus plugin pack

Events and commands

Typed lifecycle and gameplay events use class properties rather than dictionaries. Only events with a truthful pre-action native boundary expose cancellation.

player.joinPlayerJoinEventObserve
player.attackPlayerAttackEventCancellable
player.commandPlayerCommandEventCancellable
server.tickServerTickEventObserve

Compatibility contract

A plugin declares the minimum API line it requires. New BedrockPlus releases retain supported older lines; an older runtime rejects plugins requiring a newer API before their code loads.

Stable29 Oct 2026

BedrockPlus 1.1.0

  • API 1.1 is the current maximum; API 1.0 plugins remain supported.
  • Supports BDS 1.26.60.6 with a refreshed native compatibility profile.
  • Retires departing player actors before native metadata reads, preventing a server crash on disconnect.
  • Reports the managed BDS process ID, exit code and control stage if the plugin endpoint disappears.

Issue references will be attached here after the public support repository is configured.

Stable27 Oct 2026

BedrockPlus 1.0.2

  • Transient native Actor snapshot conflicts no longer stop the Bedrock server.
  • Unsafe Actor handles are quarantined and rebuilt on the next tick with rate-limited diagnostics and a recovery notice.
  • Plugins can check whether experimental Container UI is available, so disabling it does not affect unrelated plugin features.

Issue references will be attached here after the public support repository is configured.

Stable24 Oct 2026

BedrockPlus 1.0.1

  • Reuses completed scheduler callback slots during long-running plugin sessions.
  • Defines API 1.0 as the current maximum and preserves the legacy numeric API declaration.
  • Removes automatic successful plugin load and enable notices; plugin authors control their own lifecycle messages.
  • Adds a non-blocking PyPI update notice that never prevents offline startup.
Stable24 Oct 2026

BedrockPlus 1.0.0

  • First stable Windows x64 release for BDS 1.26.52.3.
  • Ships typed Python and C++ APIs with native players, entities, scoreboard, boss bars, tags and item registry foundations.
  • Introduces verified Wheel, runtime, examples, website and checksum publication gates.
